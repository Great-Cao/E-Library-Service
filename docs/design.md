-   项目类型：后端技术作业

## 决策摘要

> 本表把关键取舍前置，便于快速浏览；每条决策的备选方案、判据、代价与推翻条件见第 16 节。

| 决策 | 关键理由 | 主要代价 |
| --- | --- | --- |
| 分层单体，而非微服务 | 功能规模小，优先把职责边界做清楚 | 无法独立扩展，拆分成本留到以后 |
| SQLite + 单连接池 | 评审方零配置即可运行 | 读写都串行，不适合高写入并发 |
| 冗余 `availableCopies` + 条件更新 | 列表要显示可借数，且绝不能超借 | 存在不一致风险，靠约束与并发测试兜底 |
| 身份用 `X-User-Id` 请求头 | 原题无认证要求，但需演示多用户 | 不是安全机制，可被任意伪造 |
| 借阅建模为 `POST /books/{id}/loans` | 从属关系清晰，无需请求体 | 不适合批量借阅场景 |
| 借阅刻意不做幂等 | 重复借同一本书是合法语义 | 客户端重试会多借一册 |
| `returnedAt` 表示借阅状态 | 消除状态与时间不一致 | 无法表达续借、丢失等中间态 |
| 前端默认走 Vite 代理 | 同源，后端保持零改动 | 分离部署仍需要 CORS |

### 2.3 明确假设

源需求文件允许"对于未明确说明的需求，可自行作出合理假设"。以下假设构成实现基线，并应在 README 中同步说明：

1.  **无用户与书籍管理接口**：本期不提供注册、登录或书籍/用户的增删改接口。`User` 与 `Book` 记录仅来自可重复执行的演示数据初始化（见第 10 节），README 必须列出演示用户 ID，以便直接调用借阅接口。
2.  **身份来自请求头**：当前用户由 `X-User-Id` 请求头模拟（见第 6 节）。这是演示机制，不是安全认证。
3.  **允许重复借阅同一本书**：同一用户可同时持有同一本书的多册，总量仅受可借库存限制；当前借阅列表按借阅记录逐条返回（见第 7.5 节）。
4.  **无借期与费用**：不设借阅期限、逾期、罚款、预约或续借。
5.  **时间统一使用 UTC**：所有时间字段以 UTC 存储与序列化，采用 ISO-8601（如 `2026-10-02T15:30:00Z`），Java 侧使用 `Instant`。
6.  **ISBN 归一化（前提性假设）**：若将来提供书籍写入接口，入库前应去除连字符与空白并按 ISBN-10/ISBN-13 校验，唯一性基于归一化后的值。本期没有书籍写入接口，这条假设**没有落点**，只作为数据契约记录，不应被读成已实现的行为。
7.  **库存上限固定**：不提供修改 `totalCopies` 的接口，`availableCopies` 仅在借阅/归还时变化。
8.  **单实例部署**：按单进程、单数据库文件的单体服务交付，不承诺多实例并发与高可用。
9.  **前端只是演示**：原题只要求后端服务与 README；第 12 节的 Vue 前端是额外扩展，不引入新的后端接口，也不改变既有 API 契约。前端不做登录，演示用户固定为种子用户 1（Alice Chen）与 2（Brian Lee）。
10. **前后端默认同源**：通过 Vite 开发服务器把 `/api` 代理到后端，因此后端**无需 CORS 配置**；若改为分离部署，则属于已知取舍，见第 16 节。

### 3.1 版本策略

项目初始化时选择彼此兼容的 Java LTS、Spring Boot、Flyway、SQLite JDBC 和
Springdoc OpenAPI 版本，并将版本固定在 `pom.xml`。README 应记录 Java
版本和启动方式。具体依赖版本应在编码开始时确认，不在本设计中虚构具体版本号。

### 3.2 SQLite 适用范围

SQLite
用于本作业的小型单体服务。其写入并发能力有限，因此设计重点是正确使用事务、条件更新和约束；不将本方案描述为面向高并发生产环境的最终架构。

### 3.3 SQLite 与 JPA 关键配置

SQLite 不在 Hibernate 官方支持列表中，必须显式配置，否则应用启动或 DDL 校验会失败：

-   **方言**：引入 `org.hibernate.community.dialect.SQLiteDialect`（Hibernate community dialects），并通过 `spring.jpa.database-platform` 显式指定，不依赖 JDBC 元数据自动探测。
-   **禁止自动建表**：设置 `spring.jpa.hibernate.ddl-auto=none`（`validate` 亦可，但 SQLite 类型体系宽松，Hibernate 的列类型校验并不可靠，故本实现选择 `none` 并以集成测试验证约束），表结构完全由 Flyway 负责，避免 Hibernate 与 Flyway 争抢建表。
-   **启用外键**：SQLite 默认关闭外键约束，需在连接层启用（JDBC URL 追加 `?foreign_keys=on` 或等价的连接初始化），并由集成测试验证（见第 13.2 节）。
-   **忙等待**：通过 `busy_timeout`（JDBC URL 参数或 `PRAGMA busy_timeout`）降低并发写入直接返回 `SQLITE_BUSY` 的概率。
-   **条件更新**：库存扣减/恢复使用 `@Modifying @Query` 并读取影响行数；注意 JPA 一级缓存，必要时以 `clearAutomatically`/`flushAutomatically` 处理后再重新读取实体构造响应（见第 9.1 节）。

## 4. 架构设计

采用分层单体架构：

1.  **Controller 层**：处理 HTTP
    路由、请求头和请求参数，调用应用服务，映射响应 DTO。
2.  **Service 层**：组织业务用例、事务边界和业务流程。
3.  **Domain 层**：表达 `Book`、`User`、`Loan` 领域实体及核心规则。
4.  **Repository 层**：通过 Spring Data JPA 访问数据库。
5.  **DTO 层**：定义请求和响应结构，不直接向 API 暴露持久化实体。
6.  **Exception 层**：定义业务异常及统一错误响应映射。
7.  **Config 层**：配置应用、身份模拟、OpenAPI 等基础设施。

依赖方向以 Controller → Service → Domain / Repository 为主。Domain
不依赖 HTTP 控制器；Controller 不直接访问数据库。

系统还包含一个可选的 Vue 单页前端（见第 12 节）。它作为独立的静态应用，
仅通过第 7 节的 REST 契约与后端通信，不新增后端接口，也不改变上述分层。

## 5. 领域模型与数据模型

核心实体为 `Book`、`User`、`Loan`。

### 5.1 Book（图书）

  字段                类型建议                     规则
  ------------------- ---------------------------- ------------------------------------
  `id`                Long / SQLite INTEGER 主键   唯一标识
  `title`             String / TEXT                必填
  `author`            String / TEXT                必填
  `isbn`              String / TEXT                唯一，采用统一格式保存
  `description`       String / TEXT                可选
  `totalCopies`       Integer                      不小于 0
  `availableCopies`   Integer                      大于等于 0，且不大于 `totalCopies`
  `createdAt`         时间类型                     创建时间

说明：`isbn` 入库前按第 2.3 节规则归一化，唯一性基于归一化值；所有时间字段使用 `Instant`（UTC）。`title`、`author`、`isbn`、`totalCopies`、`availableCopies` 均为非空。

### 5.2 User（用户）

  字段          类型建议                     规则
  ------------- ---------------------------- ----------
  `id`          Long / SQLite INTEGER 主键   唯一标识
  `name`        String / TEXT                必填
  `createdAt`   时间类型                     创建时间

`name` 非空，`createdAt` 使用 `Instant`（UTC）。本期不保存密码，也不实现完整用户账户系统。用户记录用于模拟身份、建立借阅关系。

### 5.3 Loan（借阅记录）

  字段           类型建议                     规则
  -------------- ---------------------------- ------------------
  `id`           Long / SQLite INTEGER 主键   唯一标识
  `bookId`       外键                         关联 `books.id`
  `userId`       外键                         关联 `users.id`
  `borrowedAt`   时间类型                     借阅时间
  `returnedAt`   可空时间类型                 空值表示尚未归还

说明：`borrowedAt` 非空，`borrowedAt`、`returnedAt` 均为 `Instant`（UTC）。

### 5.4 关系

-   `Book 1:N Loan`：一本图书对应多条借阅记录。
-   `User 1:N Loan`：一个用户对应多条借阅记录。
-   每条 `Loan` 只关联一个用户和一本图书。

### 5.5 数据约束

-   `isbn` 唯一（基于归一化值）。
-   `books.title`、`books.author`、`books.isbn`、`users.name`、`loans.borrowed_at` 非空。
-   `total_copies >= 0`。
-   `available_copies >= 0`。
-   `available_copies <= total_copies`，以数据库 `CHECK` 约束表达，而不仅依赖应用层。
-   `loans.book_id`、`loans.user_id` 为外键。
-   SQLite 外键约束必须在连接配置中明确启用，并通过集成测试验证。
-   借阅记录归还后保留，不物理删除。
-   不单独保存 `loan_status`，通过 `returned_at IS NULL`
    判断当前是否借出，避免状态字段与归还时间冲突。

### 5.6 库存不变量

始终满足：

``` text
0 <= availableCopies <= totalCopies
```

-   初始化：`availableCopies = totalCopies`。
-   成功借阅：`availableCopies - 1`。
-   成功归还：`availableCopies + 1`。
-   失败操作不得留下部分更新。

## 6. 身份模拟与授权边界

本期通过请求头 `X-User-Id` 模拟当前用户。

-   借阅接口从该请求头解析当前用户。
-   当前借阅接口使用 `/users/me/loans`，不接受任意用户 ID 作为目标用户。
-   归还接口必须确认借阅记录属于当前用户。
-   缺少或格式无效的请求头按 `400 VALIDATION_ERROR` 处理。
-   请求头必须是正整数：非数字、`0` 或负数一律按 `400 VALIDATION_ERROR` 处理。
-   请求头对应的用户不存在时按 `404 USER_NOT_FOUND` 处理。
-   归还其他用户的借阅记录返回 `403 FORBIDDEN`（取舍见第 8.1 节）。

此机制仅用于作业演示，不是安全认证。正式认证接入时，应从已验证的认证上下文中取得用户身份，并保留服务层的所有权校验。

## 7. REST API 契约

基础路径：`/api/v1`。请求与响应使用 JSON。

### 7.1 图书列表

`GET /api/v1/books?page=0&size=20`

-   `page`：从 0 开始，默认 `0`。
-   `size`：默认 `20`，范围 `1–100`。
-   默认按 `id` 升序，保证分页排序稳定。
-   本期不提供关键字搜索或可用性筛选（见第 2.2 节）。

成功响应 `200 OK`：

``` json
{
  "items": [
    {
      "id": 1,
      "title": "Clean Code",
      "author": "Robert C. Martin",
      "isbn": "9780132350884",
      "totalCopies": 3,
      "availableCopies": 2
    }
  ],
  "page": 0,
  "size": 20,
  "totalElements": 1,
  "totalPages": 1
}
```

列表 DTO 可以省略详情专属字段，例如长描述。

### 7.2 图书详情

`GET /api/v1/books/{bookId}`

-   存在：`200 OK`，返回图书基本信息、总库存、可借库存。
-   不存在：`404 BOOK_NOT_FOUND`。

### 7.3 借阅图书

`POST /api/v1/books/{bookId}/loans`

请求头：

``` http
X-User-Id: 1
```

不需要请求体；图书 ID 来自路径，用户 ID 来自模拟身份请求头。

成功响应 `201 Created`：

``` json
{
  "id": 101,
  "bookId": 1,
  "userId": 1,
  "borrowedAt": "2026-10-02T15:30:00Z",
  "returnedAt": null
}
```

上述 ID 和时间仅用于说明格式，不是实际记录。

规则：

-   图书不存在：`404 BOOK_NOT_FOUND`。
-   用户不存在：`404 USER_NOT_FOUND`。
-   无可借库存：`409 BOOK_UNAVAILABLE`。
-   缺少或无效身份头：`400 VALIDATION_ERROR`。
-   成功创建借阅记录并减少可借库存。

**同一用户允许同时借阅同一本书的多册**，但总量受可借库存限制。本接口不是幂等的：重复提交会创建多条记录并重复扣减库存，取舍见第 9.4 节。

### 7.4 归还图书

`POST /api/v1/loans/{loanId}/return`

请求头：

``` http
X-User-Id: 1
```

成功响应 `200 OK`，返回更新后的借阅记录。

规则：

-   借阅记录不存在：`404 LOAN_NOT_FOUND`。
-   记录属于其他用户：`403 FORBIDDEN`（取舍见第 8.1 节）。
-   记录已归还：`409 LOAN_ALREADY_RETURNED`。
-   成功归还后设置 `returnedAt`，并恢复一次库存。
-   本接口天然幂等：重复调用返回 `409`，且不会重复恢复库存。

### 7.5 当前借阅

`GET /api/v1/users/me/loans?status=active&page=0&size=20`

请求头：

``` http
X-User-Id: 1
```

成功响应 `200 OK`：

``` json
{
  "items": [
    {
      "id": 101,
      "bookId": 1,
      "bookTitle": "Clean Code",
      "bookAuthor": "Robert C. Martin",
      "borrowedAt": "2026-10-02T15:30:00Z"
    }
  ],
  "page": 0,
  "size": 20,
  "totalElements": 1,
  "totalPages": 1
}
```

-   `status` 缺省时默认为 `active`；本期只接受 `active`（大小写不敏感，`ACTIVE` 同样有效），其他值按 `400 VALIDATION_ERROR` 处理。
-   分页与排序规则与图书列表一致：`page` 从 0 开始，`size` 默认 `20`、范围 `1–100`，按 `loan.id` 升序，保证结果稳定。
-   逐条返回借阅记录而非按书聚合，因为同一用户可持有多册同一本书（见第 2.3 节）；每条记录携带展示所需的书名与作者。
-   已归还记录不出现在当前借阅列表中，但仍保留在数据库。
-   用户身份来自 `X-User-Id`，不允许通过查询参数切换用户，也不允许通过 `status` 查询其他状态。

## 8. 统一错误响应

错误响应结构统一为：

``` json
{
  "error": {
    "code": "BOOK_UNAVAILABLE",
    "message": "No copies are currently available."
  }
}
```

-   `details` 仅在参数或请求头校验失败时出现，元素形如 `{"field": "X-User-Id", "reason": "must be a positive integer"}`，用于指出具体是哪个字段不合法。
-   有意不返回时间戳与请求路径：错误码与消息已足以让调用方处理，且避免向外暴露内部路由细节；后续若接入链路追踪，可再补充 `traceId`。

  错误码                      HTTP 状态 含义
  ------------------------- ----------- ------------------------
  `VALIDATION_ERROR`                400 参数或请求头无效
  `BOOK_NOT_FOUND`                  404 图书不存在
  `USER_NOT_FOUND`                  404 用户不存在
  `LOAN_NOT_FOUND`                  404 借阅记录不存在
  `BOOK_UNAVAILABLE`                409 没有可借库存
  `LOAN_ALREADY_RETURNED`           409 重复归还
  `FORBIDDEN`                       403 操作其他用户的借阅记录
  `NOT_FOUND`                       404 请求的路由或资源不存在
  `METHOD_NOT_ALLOWED`              405 该路由不支持此 HTTP 方法
  `SERVICE_UNAVAILABLE`             503 数据库繁忙（如 `SQLITE_BUSY`），可稍后重试
  `INTERNAL_ERROR`                  500 未预期的服务端错误

通过全局异常处理器映射业务异常和框架异常。不能向客户端暴露堆栈、SQL
语句、文件路径或内部异常详情。数据库繁忙错误必须映射为 `503 SERVICE_UNAVAILABLE`，不得误报为 `409 BOOK_UNAVAILABLE`。

### 8.1 状态码取舍

-   **归还他人借阅返回 `403` 而非 `404`**：`403` 语义更直白，但会向调用方暴露"该借阅记录存在但不属于你"。本期选择 `403`，因为身份是演示用的 `X-User-Id`，不存在真实越权风险；若接入真实认证并要求隐藏资源存在性，应改为 `404 LOAN_NOT_FOUND`。

## 9. 事务与并发策略

### 9.1 借阅

借阅必须在一个数据库事务内完成：

1.  校验当前用户和图书存在。
2.  执行带条件的库存更新，仅当 `available_copies > 0` 时扣减。
3.  检查更新影响行数；未扣减成功则返回 `409 BOOK_UNAVAILABLE`。
4.  创建 `Loan` 记录。
5.  提交事务；任一步骤失败则回滚。

不能采用仅在 Java 层读取库存后无条件减一的方式，否则并发请求可能超借。

### 9.2 归还

归还必须在一个事务内完成：

1.  查询借阅记录。
2.  检查记录所有权。
3.  仅当 `returned_at IS NULL` 时更新归还时间，并检查受影响行数。
4.  仅在状态更新成功后恢复库存。
5.  提交事务；任一步骤失败则回滚。

重复归还不能重复增加库存。

### 9.3 SQLite 约束

-   在实际 SQLite 数据库上验证事务和外键行为。
-   正确识别数据库锁竞争 / `SQLITE_BUSY`，不要将其误报为业务冲突。
-   不承诺高并发生产级吞吐量。
-   通过集成测试验证竞争场景不会产生负库存或重复恢复库存。
-   开发数据库与测试数据库隔离；测试使用独立数据库文件或临时数据库。

### 9.4 借阅幂等性

借阅接口不是幂等的：同一用户可重复借阅同一本书（见第 2.3 节），因此客户端重试或重复提交会创建多条记录并重复扣减库存。本期有意接受该行为以保持演示简洁；生产化时应引入 `Idempotency-Key` 请求头或去重表。归还接口通过"仅当 `returned_at IS NULL` 时更新"实现天然幂等，重复调用返回 `409 LOAN_ALREADY_RETURNED`，且不会重复恢复库存。

## 10. 数据库迁移与演示数据

使用 Flyway 版本化迁移创建和演进表结构。表结构由版本化迁移负责；演示数据通过 Flyway 可重复迁移加载，保证幂等。

推荐机制：

-   **表结构**：`V1__create_schema.sql`，包含三张表、非空约束、`CHECK` 约束、`UNIQUE(isbn)` 与外键。
-   **演示数据**：`R__seed_demo_data.sql`（Flyway repeatable 迁移），使用稳定主键与 `INSERT ... ON CONFLICT(id) DO NOTHING` / `ON CONFLICT(isbn) DO NOTHING`，重放不会产生重复行。
-   **演示用户**：种子数据包含固定 ID 的用户（例如 `1`、`2`）与若干图书，README 列出这些 ID，便于直接调用 `X-User-Id`。
-   **不覆盖用户数据**：种子脚本只做"缺则插入"，不更新已有行，因此正常启动不会覆盖用户数据。

实施要求：

-   迁移文件命名遵循 Flyway 版本化约定。
-   演示数据必须幂等且可重复执行。
-   演示数据初始化有明确触发方式（Flyway 迁移），不在每次正常应用启动时无条件覆盖用户数据。
-   测试使用独立的测试配置与数据库。

## 11. OpenAPI 文档

使用 Springdoc OpenAPI 自动生成 API 文档（Spring Boot 3 使用 `springdoc-openapi-starter-webmvc-ui`）。

规划地址（以最终依赖和配置为准）：

-   OpenAPI JSON：`/v3/api-docs`
-   Swagger UI：`/swagger-ui/index.html`

文档至少包括：

-   五个业务接口的用途、参数、请求头。
-   请求与响应示例。
-   HTTP 状态码和统一错误模型。
-   `X-User-Id` 身份模拟说明。
-   分页规则与 `status=active` 的行为。
-   错误响应：控制器用 `@ApiResponses` 声明共享的 `ErrorResponse` 模型；`@CurrentUserId`
    参数用 `@Parameter(hidden = true)` 标注，避免被误发布成必填查询参数。

**两点 springdoc 行为记录（都实测确认过）**：

1.  只要方法或类上出现 `@ApiResponses`（或 `@Operation(responses = ...)`），springdoc 就
    **不再自动生成基于返回类型的成功响应**。所以每个方法都显式声明了 `200`/`201`，
    否则 Swagger UI 上会只剩错误码。
2.  泛型 `PageResponse<T>` 在注解里只能声明为原始类型，其 `items` 元素类型不会被解析
    （分页信封的 `page`/`size`/`totalElements`/`totalPages` 仍完整可见）。这是为换取
    "响应码精确、无过度声明"而接受的展示层限制。

### 12.4 页面与交互

  路由              视图                主要交互

-   列表视图用请求序号守卫丢弃过期响应，避免快速翻页时旧响应覆盖新页码数据；翻页按钮在加载期间禁用。

### 12.6 前端实现约定

-   不在前端复制业务规则：库存是否充足、借阅记录归属、重复借阅与重复归还一律由后端裁决；

12. 测试不依赖开发者本地已有数据库文件。

并发借阅测试必须确定性执行：使用固定线程数（如 8）与 `CountDownLatch` 同时向同一本书发起借阅，断言最终 `availableCopies >= 0`、成功借阅数等于 `totalCopies - availableCopies`，且不存在超借。测试在真实 SQLite 文件数据库上运行，并验证外键与 `CHECK` 约束确实生效。

**边界说明**：该测试的连接池上限为 1，8 个线程实际上是排队执行，因此它验证的是"并发请求下最终状态仍满足不变量"，而**不是**"条件更新能扛住真正的并发写"。要验证后者需要放开连接池并接受 `SQLITE_BUSY` 重试。这里刻意选择确定性优先于并发压力，并把这条限制写出来而不是藏着。

## 16. 设计取舍与已知限制

下表列出关键决策的备选方案、判据、代价与推翻条件。"代价"与"何时推翻"两列是刻意保留的：
能说清自己方案的缺点和边界，比论证它完美更有说服力。

| 决策 | 备选方案 | 判据 | 代价 / 风险 | 何时推翻 |
| --- | --- | --- | --- | --- |
| 分层单体 | 微服务 | 功能规模小，4--6 小时预算 | 无法独立扩展 | 领域拆分或团队规模变大时 |
| SQLite + 单连接池 | 独立数据库服务 | 评审方零配置即可运行 | 读写全部串行 | 写入并发成为瓶颈时改用服务型数据库 |
| 冗余 `availableCopies` | 每次实时统计未归还借阅 | 列表要显示可借数，且绝不能超借 | 存在不一致风险 → 条件更新 + `CHECK` + 并发测试兜底 | 冗余字段成为锁竞争热点时，改为对账或物化统计 |
| 身份用 `X-User-Id` 请求头 | 路径/查询参数、真实认证 | 原题无认证要求，但需演示多用户 | 不是安全机制，可被任意伪造 | 接入真实认证后；服务层所有权校验保留不变 |
| 借阅建模为 `POST /books/{id}/loans` | `POST /loans`（请求体带 bookId） | 从属关系清晰，无需请求体 | 不适合批量借阅 | 出现批量借还需求时改为顶层资源 |
| 当前借阅逐条返回 | 按书聚合 + 数量 | 同一用户可持多册，每次归还只针对一条记录 | 前端需自行聚合展示 | 前端需要"按书汇总"视图时补聚合参数 |
| `returnedAt` 表示借阅状态 | 独立 `status` 字段 | 彻底消除状态与时间不一致 | 无法表达续借、丢失等中间态 | 引入续借/遗失/罚金状态机时 |
| 借阅刻意不做幂等 | `Idempotency-Key` + 去重表 | 重复借阅同一本书是合法语义 | 客户端重试会多借一册 | 出现真实重试或网络不稳定场景时 |
| 统一错误信封 + 业务错误码 | 直接透出 HTTP 状态与框架异常 | 客户端可稳定分支处理 | 需维护错误码文档与映射 | 对外提供 SDK 时可生成错误码枚举 |
| Flyway 独占 schema（`ddl-auto=none`） | Hibernate 自动建表或 `validate` | SQLite 类型宽松，`validate` 不可靠 | 失去启动期 schema 校验 | 换到类型严格的数据库并开启 `validate` 时 |
| 前端默认走 Vite 代理 | 后端增加 CORS 配置 | 演示同源，后端保持零改动 | 分离部署时仍需 CORS | 前后端独立部署时 |
| 前端不引入 Pinia 与组件库 | 完整前端工程 | 三个页面、一个共享状态 | 页面变多后需重构状态管理 | 前端功能显著扩张时 |
| 不从 Maven 触发 npm | `frontend-maven-plugin` | 避免 Maven 构建依赖 Node 与网络 | 单包交付需手动两步命令 | 需要 CI 一键产出含前端的单一产物时 |
| 错误响应恒为 JSON 信封，不做内容协商 | 按 `Accept` 头协商错误格式 | 客户端只需处理一种错误格式 | `Accept` 完全不含 JSON 时会协商失败并返回 500（真实浏览器带 `*/*`，不受影响） | 出现必须支持其他错误格式的客户端或网关时 |
| 不自定义 Spring 内置的 `/error` 端点 | 实现自定义 `ErrorController` 统一信封 | 该端点不属于对外契约（对外是 `/api/v1/**`） | 直接访问 `/error` 会看到 Spring 默认结构（含 `timestamp` 与 `status: 999`） | 需要连内部端点也严格统一响应格式时 |

**交付优先级**：在 4--6 小时预算内，优先级为"五个接口可用 + README + 核心单元/集成测试"，
OpenAPI、并发测试与可重复种子迁移为增强项。原题更看重思考过程与取舍而非功能数量，
时间紧张时宁可少做并讲清取舍。
